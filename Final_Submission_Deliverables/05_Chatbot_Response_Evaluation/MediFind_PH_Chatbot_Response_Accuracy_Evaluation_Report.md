# MediFind PH — Chatbot Response Accuracy Evaluation Report

**Evaluation date:** 11 November 2026 (Asia/Manila)  
**Baseline:** Configuration D — chunk 800, overlap 200, top-k 3; 762 Chroma chunks; MiniLM embeddings; FLAN-T5 Base.  
**Execution:** 36 actual `POST /api/chat` requests against the running FastAPI service. Production code and the baseline were not modified.

> This is an engineering evaluation, not completion of the user's Phase 5 manual tests. Final manual/UAT testing remains pending. The 36 cases do not prove that all 94 medicine records are correct.

## Executive conclusion

MediFind PH is strong on structured single-record facts, exact formulation comparisons, record enumeration, unknown-entity handling, and medical-safety refusals. It is **not yet consistently reliable for broad leaflet-section questions or citation precision**. The most serious failures were: one named Bonamine formulation was dropped, Canesten warnings were replaced by unrelated leaflet text, and an explicit Gaviscon suspension comparison included a sibling chewable formulation.

The automated checker reported 30 PASS and 6 FAIL. Engineer review found that 14 otherwise useful answers had incomplete or overbroad citations, producing the stricter reviewed result below.

| Result set | Total | PASS | PARTIAL PASS | FAIL | Strict pass rate | PASS + PARTIAL |
|---|---:|---:|---:|---:|---:|---:|
| Automated checks | 36 | 30 | 0 | 6 | 83.3% | 83.3% |

## Method and evidence controls

- Expected answers were fixed before execution from the three PDF registration-record pages and verified leaflet evidence. They were not generated from chatbot output.
- Every test stored the raw API answer, status, structured cards, citations, passages, HTTP status, and latency.
- Automated checks covered relevance, required/forbidden facts, completeness, exact registration-number set, expected PDF/page presence, nonempty passages, and safety status.
- Engineer review then checked whether each returned passage actually supported the statement and whether irrelevant leaflet pages were attached.
- Sources were restricted to the three repository PDFs; no external medical source was used.

## Strong areas

- **Safety gates:** 6/6 unknown/diagnosis/dosage/price/recommendation/discount cases behaved safely; no card or citation was fabricated.
- **Structured facts:** exact generic names, ingredients, strengths, registration numbers, manufacturers, and record pages were correct in the passing field cases.
- **Most formulation comparisons:** Flanax, Mucosolvan, Sinecod, Dulcolax, Eye Mo, Kremil-S, and Gaviscon Double Action stayed factually separated.
- **Cross-volume coverage:** all three PDF volumes were exercised, not only Biogesic, Allerkid, and Gaviscon.

## Common error categories

1. **Citation over-inclusion:** `_assemble_sources` appends all leaflet pages for every matched registration, even for simple field lookups and record listings. Correct answers therefore often include unrelated passages.
2. **Leaflet section boundary/OCR failure:** Canesten warning extraction accepted mixed manufacturer and pregnancy text while omitting the requested warnings. Dolfenal side-effects fallback returned only one adverse effect.
3. **Entity-to-quantity binding errors:** comparison quantities are matched globally. “Dolfenal 250 mg” caused the Gaviscon 250 mg chewable sibling to survive an otherwise explicit suspension comparison.
4. **Multi-record response template incompleteness:** enumeration returns generic name, strength/form, and registration number but ignores requested manufacturer fields; the cards contain them, but the prose does not answer the request directly.
5. **Citation type confusion:** an extra Dolfenal leaflet page was labeled as a registration-record page in the source-summary answer.

## Root causes and proposed system-wide improvements

| Root cause | Evidence | Proposed reusable improvement |
|---|---|---|
| Intent-insensitive citation assembly | `backend/rag/pipeline.py` adds every leaflet page for every matched record. | Pass answer intent and section metadata into citation assembly; emit only record pages and the specific section pages used by claims. |
| Fixed multi-record response template | Enumeration omits manufacturer even when asked. | Parse requested fields into an answer plan and render those fields for every matched record. |
| Global quantity matching in comparisons | Dolfenal 250 mg matched Gaviscon 250 mg chewable sibling. | Parse comparison mentions into per-entity slots and bind strength/form tokens locally before merging. |
| Weak OCR section validation | Canesten mixed manufacturer/pregnancy content passed as warnings. | Use heading-bounded page segments, reject cross-heading content, detect column interleaving, and return an explicit OCR limitation when confidence is low. |
| LLM fallback compresses list questions | Dolfenal side-effects answer contained one item only. | Prefer deterministic full-section summaries with list coverage checks; require minimum evidence-item coverage for plural questions. |
| Citation metadata conflates types | Dolfenal page 24 labeled both record and leaflet. | Store a citation type (`registration_record`, `leaflet_section`, `retrieval_hit`) and render each category separately. |
| No claim-to-citation verifier | Non-supporting pages can appear without detection. | Before returning, map each factual sentence/field to at least one supporting passage and drop unreferenced citations. |

## Remaining limitations

- Only 36 representative questions were executed; the 94-record catalog was not exhaustively validated.
- The live API was evaluated, but frontend visual behavior, expanded-citation UX, accessibility, and copy behavior were not manually tested.
- PDF OCR/transcription quality is itself imperfect; the report preserves evidence when the application exposes OCR corruption.
- No concurrency, load, cold-start, or repeated-run variance testing was performed.
- The user's Phase 5 manual tests remain **not executed** and must be completed separately.
